## 開始之前

你需要這五個帳號，都可以用現有的：

| 服務 | 做什麼用 | 要花錢嗎 |
|---|---|---|
| LINE | 機器人本體 | 免費 |
| Firebase | 存名片資料與圖片 | 免費額度就夠 |
| OpenAI | 辨識名片 | **要儲值**，一個月約 5 到 15 美元 |
| Google Cloud | 讀你的日曆判斷在哪認識的 | 免費 |
| Vercel | 放這個機器人 | 免費 |

**照順序做，不要跳。** 後面的步驟會用到前面拿到的東西。

準備一個記事本，過程中會拿到六、七組要貼來貼去的字串。

## 步驟 1：建立 LINE 機器人

### 1-1 建立 Provider

到 [LINE Developers Console](https://developers.line.biz/console/)，用你平常的 LINE 帳號登入。

Provider 就是「這些機器人是誰的」，名字填你的公司名就好。

![建立 Provider](images/01-line-provider.png)

### 1-2 建立 Messaging API 頻道

在剛建好的 Provider 底下建立頻道，類型選 **Messaging API**。

![選擇頻道類型](images/02-line-channel-type.png)

名稱就是使用者在 LINE 裡看到的機器人名字，之後可以改。

### 1-3 拿 Channel secret

切到 **Basic settings** 分頁，往下找到 Channel secret，複製起來貼到記事本。

![Channel secret](images/03-line-secret.png)

### 1-4 拿 Channel access token

切到 **Messaging API** 分頁，**一路捲到最底部**，找到 Channel access token，按 **Issue**。

![發行 token](images/04-line-token.png)

> ⚠️ 這個 token 視窗關掉就看不到了，馬上貼到記事本。
>
> 它在頁面最下面，很多人捲不到底就以為沒有這個功能。

### 1-5 關閉自動回覆

同一頁往上找 **Auto-reply messages**，點進去把自動回覆**關掉**。

![關閉自動回覆](images/05-line-autoreply.png)

> 不關的話，LINE 的罐頭訊息會蓋掉機器人的回覆，症狀看起來很像機器人壞了。

## 步驟 2：建立資料庫（Firebase）

這一步是整份手冊最容易出錯的地方，慢慢來。

### 2-1 建立專案

到 [Firebase Console](https://console.firebase.google.com/) 建立新專案，名字隨便取。

![建立 Firebase 專案](images/06-firebase-create.png)

### 2-2 開 Firestore，地區選 asia-east1

左側選單找到 **Firestore Database**，建立資料庫。

![Firestore 地區](images/07-firestore-region.png)

> ⚠️ **地區一定要選 `asia-east1`（台灣）。**
>
> 建立之後**不能更改**，選錯只能砍掉整個專案重來。

### 2-3 開 Storage，地區一樣

左側選單找到 **Storage**，開始使用，地區同樣選 `asia-east1`。

![Storage 地區](images/08-storage-region.png)

### 2-4 下載金鑰檔

左上齒輪 → **專案設定** → **服務帳戶** → **產生新的私密金鑰**。

![產生私密金鑰](images/09-firebase-key.png)

會下載一個 JSON 檔，用記事本打開，裡面有三個等一下要用的欄位：

- `project_id`
- `client_email`
- `private_key`（很長的那一串，**連頭尾的引號一起複製**）

### 2-5 記下 bucket 名稱

回到 Storage 頁面，最上方有一行長得像 `你的專案.firebasestorage.app`，複製起來。

![Storage bucket](images/10-storage-bucket.png)

## 步驟 3：OpenAI 金鑰

### 3-1 建立 API key

到 [platform.openai.com/api-keys](https://platform.openai.com/api-keys) 建立新的 key，複製到記事本。

![建立 API key](images/11-openai-key.png)

### 3-2 儲值

到 **Billing** 儲值，建議先存 20 美元。

![OpenAI 儲值](images/12-openai-billing.png)

> 不儲值的話機器人會回「credit balance 不足」。
>
> 一個人用一個月大概 5 到 15 美元，看你收多少名片。

## 步驟 4：部署上線（Vercel）

### 4-1 匯入專案

到 [vercel.com/new](https://vercel.com/new)，匯入這個 repo。

![匯入 repo](images/13-vercel-import.png)

不用先 fork，直接匯入就行。

### 4-2 填環境變數

**先不要按 Deploy。** 展開 **Environment Variables**，把下面 13 項全部填好。

![填環境變數](images/14-vercel-env.png)

| 變數名稱 | 從哪裡來 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 步驟 1-4 |
| `LINE_CHANNEL_SECRET` | 步驟 1-3 |
| `ALLOWED_LINE_USER_IDS` | 先填 `PLACEHOLDER`，步驟 7 再換掉 |
| `OPENAI_API_KEY` | 步驟 3-1 |
| `FIREBASE_PROJECT_ID` | 金鑰 JSON 的 `project_id` |
| `FIREBASE_CLIENT_EMAIL` | 金鑰 JSON 的 `client_email` |
| `FIREBASE_PRIVATE_KEY` | 金鑰 JSON 的 `private_key`，**連引號一起貼** |
| `FIREBASE_STORAGE_BUCKET` | 步驟 2-5 |
| `GOOGLE_CLIENT_ID` | 步驟 5 會拿到，先空著 |
| `GOOGLE_CLIENT_SECRET` | 步驟 5 會拿到，先空著 |
| `ADMIN_PASSWORD` | 自己設一組強的，後台登入用 |
| `CRON_SECRET` | 隨便一串亂碼都行 |
| `NEXT_PUBLIC_BASE_URL` | 先隨便填，4-3 拿到網址再回來改 |

> `FIREBASE_PRIVATE_KEY` 最容易出錯。裡面的 `\n` 是正確的，**不要自己換成真的換行**。

### 4-3 部署並記下網址

按 Deploy，等一兩分鐘，記下拿到的網址。

![部署完成](images/15-vercel-deployed.png)

從這裡開始，下面寫「你的網址」就是指這一個。

## 步驟 5：讓機器人讀你的日曆

這一步讓機器人自動判斷「這張名片是在哪認識的」。不做也能用，只是場合要自己補。

### 5-1 啟用日曆 API

到 [Google Cloud Console](https://console.cloud.google.com/)，**左上角選到步驟 2 建立的那個專案**。

**API 與服務** → **程式庫** → 搜尋 `Google Calendar API` → 啟用。

![啟用日曆 API](images/16-calendar-api.png)

### 5-2 設定同意畫面

**API 與服務** → **OAuth 同意畫面** → 選「外部」→ 填基本資料。

**測試使用者要加上你自己的 Gmail**，不加的話授權會被擋。

![OAuth 同意畫面](images/17-oauth-consent.png)

### 5-3 建立憑證

**API 與服務** → **憑證** → 建立 **OAuth 用戶端 ID**，類型選「網頁應用程式」。

![建立憑證](images/18-oauth-client.png)

### 5-4 填重新導向網址

**已授權的重新導向 URI** 填：

```
https://你的網址/api/auth/google/callback
```

![重新導向 URI](images/19-redirect-uri.png)

建立之後拿到 Client ID 與 Client Secret，回 Vercel 填進環境變數。

## 步驟 6：把 LINE 接上

### 6-1 填 Webhook 網址

回到 LINE Developers 的 **Messaging API** 分頁，Webhook URL 填：

```
https://你的網址/api/line/webhook
```

填完把 **Use webhook** 打開。

![設定 webhook](images/20-line-webhook.png)

### 6-2 驗證

按 **Verify**，應該顯示 Success。

![驗證成功](images/21-webhook-verify.png)

沒成功的話多半是網址打錯，或 Vercel 還在部署。

## 步驟 7：只讓自己能用

**這步不要省略。** 不設白名單等於任何人加好友都能用，燒的是你的 OpenAI 費用。

### 7-1 找出你的 LINE userId

用手機加機器人好友（Messaging API 分頁有 QR Code），隨便傳一則訊息。

你不會收到回覆，這是正常的，因為剛才填的是 `PLACEHOLDER`。

到 Vercel 的 **Logs**，找這一行：

```
Blocked non-allowlisted user: U1234567890abcdef...
```

![在 Logs 找 userId](images/22-vercel-logs.png)

`U` 開頭那 33 碼就是你的 userId。

### 7-2 填回去並重新部署

把 `PLACEHOLDER` 換成剛才那串 userId，順便把 `NEXT_PUBLIC_BASE_URL` 改成真正的網址。

![填回 userId](images/23-vercel-redeploy.png)

> ⚠️ **改完環境變數一定要重新部署**，不然不會生效。

---

## 步驟 8：裝上選單

底圖已經附在專案裡，不用自己做。

把下面整段貼到終端機（Mac 的「終端機」App），把兩個地方換成你自己的：

```bash
SITE="https://你的網址"; PW="你的ADMIN_PASSWORD"
COOKIE=$(curl -s -i -X POST "${SITE}/api/admin/auth" -H "Content-Type: application/json" \
  --data-binary "{\"password\":\"${PW}\"}" | grep -i '^set-cookie:' \
  | sed 's/^[Ss]et-[Cc]ookie: //' | cut -d';' -f1)
curl -s -X POST "${SITE}/api/admin/richmenu" -H "Cookie: ${COOKIE}"
```

回到 LINE，底部就會出現六格選單。

![六格選單](images/24-richmenu.png)

## 卡住了怎麼辦

先跑健康檢查，一次確認四個子系統：

```bash
curl -H "Authorization: Bearer 你的CRON_SECRET" https://你的網址/api/health
```

全過回 200，哪一項掛掉它會直接告訴你。

| 症狀 | 多半是 |
|---|---|
| 完全沒回應 | LINE token 失效，或 Use webhook 沒開 |
| 回罐頭訊息 | Auto-reply messages 沒關（步驟 1-5） |
| 回「發生錯誤」 | 環境變數少填，跑健康檢查看是哪一項 |
| 名片圖顯示不出來 | `FIREBASE_STORAGE_BUCKET` 填錯 |
| 場合一直是「未判定」 | 日曆沒授權，或當下日曆上沒有行程 |

還是不行的話，讀錯誤紀錄（接續步驟 8 的 `${COOKIE}`）：

```bash
curl "${SITE}/api/admin/errors?limit=5" -H "Cookie: ${COOKIE}"
```

裡面會寫失敗的確切原因。
